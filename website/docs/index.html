Docs

Set up Bento, connect a project, and run your work through it with Claude Code and Codex.

Setup

You need Python 3.9+ and git, plus Claude Code, Codex, or both. Bento is built and tested on macOS. Linux is untested. Windows won't work, because Bento relies on Unix file locks.

git clone https://github.com/ckoglmeier/bento.git ~/bento
mkdir -p ~/.local/bin
ln -s ~/bento/kb ~/.local/bin/kb
kb init ~/bento-data --owner yourname
kb install-agents

If your shell can't find kb, add that folder to your path and open a new terminal:

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc

The repo holds only code. Your board, docs, and plans live in the workspace folder on your machine. While it runs, Bento snapshots that folder to its own local git repo about once a minute, and kb history lists the snapshots. It never pushes them anywhere.

kb install-agents adds a short marked section to ~/.claude/CLAUDE.md and ~/.codex/AGENTS.md, and lets Codex's sandbox write to the workspace.

First five minutes

  1. Connect a project and open the board: 
    kb connect ~/code/my-app --import-docs
kb open
  2. In that project, ask Claude Code or Codex: "Read our backlog and add the next few epics to Bento." They land in Backlog.
  3. On the board, drag the one you want first into Next.
  4. Ask your agent "What's next?" It answers from the board and changes nothing. Tell it to pick the work up, and it claims the card and finishes into Review for you to check.

How it works

Every card is an epic: a meaningful group of work with one clear "done when". Small tasks go inside the epic's plan, not on the board.

The rules are short. Asking "what's next?" only reads. Agents claim a card before they start, finish into Review, and never move a card to Done. That call is yours. Agents put new work they notice in Backlog and don't start it. If one is stuck on a real decision, it blocks the card and tells you.

Agents get these rules from kb rules, which prints AGENTS.md. Claiming is atomic, so two agents can't take the same card.

The board

kb open opens the board at http://127.0.0.1:4747, and starts it in the background if it isn't running. You can also tell your agent "open bento". The board has four views:

  • Delivery: what to take up next, what each item still needs from you, and what is ready to verify.
  • Calendar: milestones across projects, and how the work feeding each one stands. Drag a milestone onto a date to move it.
  • Scratchpad: loose notes and ideas. Agents never pick these up, and any of them can become an epic. Say "note for bento" in Claude Code or Codex, and the agent saves a short summary of the discussion here.
  • Board: the kanban columns.
ColumnMeaningWho puts cards here
BacklogEpics nobody has committed toAnyone
NextCommitted work. The top card goes first.You, or a handoff you asked for
DoingSomeone is working on itWhoever claims it
ReviewFinished, waiting for you to checkWhoever did the work

Docs and plans

Connecting a project registers it in your workspace and adds nothing to its repo. Bento recognizes the project by its git remote, so every clone and worktree is connected automatically. --import-docs copies Markdown from docs/, plus root files like BACKLOG.md and ROADMAP.md, from the default branch into products/my-app/.

Imported docs are a copy. Decide which version is the real one: keep editing in the workspace and leave a pointer in the repo, or re-run kb import to refresh. A re-import overwrites workspace edits to those files.

Pull only what's worth doing soon onto the board. The --source flag points back to where the detail lives:

kb add "Saved searches" --source docs/BACKLOG.md#release-1 --release "Release 1" --done-when "..."

An epic can have one of four kinds of plan, which you can read, approve, or request changes on from the board:

KindCovers
implementationBuilding something
testingVerifying built epics as a group. It can't start until they reach Review.
releaseShipping a set of epics, with its exit gate and rollback
writingA piece of writing, often timed to warm up an audience before a release
kb plan testing "Search" --epics 14

On the board you can edit any doc in place, or start a Codex or Claude Code thread on it.

Handoffs

Iterate with one agent, then hand epics and a plan to another:

kb plan implementation "Search" --epics 12 13
kb handoff 12 13 --to claude --plan products/my-app/plans/implementation-search.md --as codex

The receiver runs kb claim 12 13 --as claude, reads the plan, and follows it. Handing off doesn't start an agent. Someone still has to ask it to pick the work up.

Hearing back without polling

kb service install

This runs Bento in the background on macOS and starts it at login. An agent that pushes work hears back once when the whole set reaches Review, or right away if an epic gets blocked:

  • Codex: the service runs codex exec resume on the session that pushed.
  • Claude Code: the session runs kb wait 12 13 as a background command, which sleeps on a kernel file event and wakes the session when it exits.

The web board updates live the same way. For your own alerts on a phone, Slack, or anything else, add a command to bento.json in your workspace. It receives the event as JSON on stdin, plus $BENTO_TITLE and $BENTO_MESSAGE:

{ "notify": { "command": "curl -s -d \"$BENTO_MESSAGE\" https://ntfy.sh/your-private-topic" } }

Milestones

Dates belong on milestones and releases, not on ordinary epics. A milestone is a named moment with one date, such as a launch or a publish date. Epics feed it through needs, and milestones in different projects can depend on each other.

kb add "Essay publishes" --kind milestone -p writing --target 2026-12-01 --needs 12,13

Each one can have a doc with its theme, acceptance criteria, and release notes. Start one with kb plan milestone "Essay publishes" --epics 14. A milestone is at risk if a dependency is blocked, a dependency is dated after it, or dependencies are open with 7 days or fewer left.

Recurring reports

kb report add "App daily usage" --thread <codex-thread-id> -p my-app --schedule "Daily at 2:00"

The Reports panel on the board links to each report's thread, filtered by project. A report job can also post a dated copy with kb report post "App daily usage" report.md, which keeps its history in products/my-app/reports/ where people and agents can read it.

Commands

kb --help lists everything. These are the ones you'll use most:

kb                               the board across projects (-p my-app, --kind testing, --all, --json)
kb next --as codex               best card for you, changes nothing
kb show 12                       one card in full
kb claim --as codex              take the best card (or: kb claim 12 13 --as codex)
kb add "title" --done-when "..."  add an epic to Backlog
kb add "title" --to scratchpad   save a note or idea
kb plan testing "Search" --epics 14
kb push 12 13 --to claude        hand epics over, with or without a plan
kb wait 12 13                    sleep until they reach Review or get stuck
kb wake 12 13                    have this Codex session resumed when they finish
kb set 12 needs "#9"             change a field
kb note 12 "text" --as codex     add a dated note
kb block 12 "reason"             flag a card as stuck (kb unblock 12 clears it)
kb review 12 --as codex --note "text"
kb move 12 next --top            move or release a card
kb delete 12                     move a card to TRASH.md (kb restore 12 undoes it)
kb calendar                      milestones and their dependencies
kb docs                          product docs and plans
kb projects                      connected projects
kb archive                       move Done cards to ARCHIVE.md
kb history                       local snapshots of your workspace
kb open                          open the web board, starting it if needed
kb serve                         run the web board in this terminal

Update or remove

cd ~/bento && git pull

kb uninstall-agents removes what kb install-agents added and leaves your workspace alone. kb service uninstall stops the background service if you turned it on.
